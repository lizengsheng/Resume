# 设计文档

## 产品目标

提供一个与个人技术博客属于同一视觉体系、但明确面向招聘场景的通用个人作品集。在线博客是颜色、字体、内容宽度、导航与间距的视觉基准；站点仍让招聘人员优先了解候选人、简历、项目和技术能力，并允许维护者只修改集中配置、头像文件和项目 Markdown，而无需改页面组件。

## 范围与非目标

- 首页采用约 768px 的窄版居中布局，连续展示资料、三项可配置事实、操作入口、精选项目与关于内容。
- 首页与项目列表自动读取项目内容集合，不写死项目数量或项目名称。
- 每个项目自动生成详情页，并提供独立的全部项目页。
- 提供不含手机号的公开 PDF 简历并支持 GitHub Pages 部署。
- 提供外部技术博客入口；不包含后台、表单、登录或分析脚本。

## 用户旅程

1. 招聘人员进入首页，在紧凑资料卡中看到头像、姓名、岗位方向和三项事实。
2. 继续向下浏览精选项目，或进入全部项目页。
3. 在连续的关于章节查看可配置的简介、能力和教育背景。
4. 进入任意项目详情，或下载简历、打开博客、GitHub 和邮箱入口。

## 行为与内容

- 导航沿用博客的轻量层级：`Li Zengsheng · Portfolio`、首页、项目、博客和主题切换。
- 浅色使用 `#fdfdfd` 背景、`#282728` 正文、`#006cac` 强调与 `#ece9e9` 分隔；深色使用 `#212737` 背景、`#eaedf3` 正文与 `#ff6b01` 强调。
- 页面采用系统中文字体、纯色背景、细分隔线、低圆角和克制动效，不引入博客的文章、搜索、RSS、归档或页面过渡功能。
- `src/config.ts` 集中维护站点元数据、姓名、描述、头像路径、统计项、联系方式、关于页内容和首页文字。
- 对外展示名统一使用 `Li Zengsheng`；公开项目数量由非草稿 Markdown 自动计算。
- `public/profile.jpg` 是网站头像；直接替换同名文件即可更新，无需修改组件。
- 项目卡由 `src/content/projects/*.md(x)` 自动生成；首页显示 `featured` 项目，项目页显示全部非草稿项目。
- 项目封面、时间、指标和外链均允许省略，正文保持自由 Markdown/MDX。
- 电话和微信不进入 HTML、PDF、源码或元数据。
- 页面默认跟随系统明暗主题，并提供本地持久化的主题切换。

## 内容模型

- 必填项目元数据：`title`、`summary`。
- 可选项目元数据：`slug`、`period`、`tags`、`metrics`、`cover`、`featured`、`draft`、`order`、`externalUrl`。
- 项目正文完全由 Markdown/MDX 决定，不要求固定章节。

## 边界情况

- 禁用 JavaScript 时，个人资料、精选项目和关于内容仍按正常顺序完整可读；JavaScript 只用于主题切换与手机菜单增强。
- GitHub Pages 子路径下，页面、图片、SVG、PDF、404 返回链接均不得跳回域名根路径。
- 小屏幕下资料卡、按钮和项目卡改为单列，中文长技术词可安全换行。

## 验收标准

- 页面颜色、字体、内容宽度、导航和留白与在线博客属于同一视觉体系，同时保持招聘作品集的信息优先级。
- 替换 `src/config.ts`、`public/profile.jpg` 或项目 Markdown 后不需要修改 Astro 页面组件。
- 首页、项目列表和项目详情无手机号或虚构链接。
- 桌面与移动端无水平滚动、遮挡、低对比度或焦点不可见问题。
- 生产构建通过，公开入口在 `/Resume` 下正确生成。
- 每次授权的本地更新在验证后提交到 `origin/main`，Pages 工作流成功并完成线上链接检查。
- PDF 为紧凑单页且经渲染检查无裁切或缺字。
